Project Overview

USB monitoring and access-control concept

About the Project

The Smart USB Activity Detection and Access Control System is a planned desktop-based security application focused on monitoring USB device connections and controlling access before file access is permitted.


The system is designed to detect connected USB storage devices, collect available device information, record activity and provide an owner-approval workflow.

Security-focused Desktop Application

Problem Statement

USB devices can introduce security risks

USB Access Security

Unknown or unauthorized USB storage devices can introduce security risks to computers. This project proposes a controlled workflow where a connected USB device can be detected, monitored and placed into a restricted or pending state before access is approved.

Project Objectives

Core objectives described in the project documentation

01. USB Detection

Detect connected USB storage devices.

02. Device Information

Collect available information such as device name, manufacturer and serial number.

03. Access Control

Provide an approval workflow before access is allowed.

04. Activity Monitoring

Record USB activity and access decisions for later review.

System Workflow

Proposed USB access-control process

1
USB Connected

A USB storage device is connected to the computer.

2
Device Detection

The system detects the connected USB device.

3
Information Collection

Available device information and connection time are collected.

4
Restricted / Pending State

The device enters the proposed restricted or pending state.

5
Access Request

An access request is presented to the owner.

6
Owner Approval

Access can follow direct approval or password-protected approval.

7
Activity Logging

Access decisions and relevant activity are recorded for review.

Access Control

Two proposed approval methods

Direct Access Approval

The owner can directly approve access to the detected USB device.

Password Protected Access

Access can be protected using a password. Failed authentication attempts are intended to be logged.

Future Password Recovery

The project documentation describes a future forgot-password mechanism using OTP-based password reset.

Security Considerations

Important security practices in the project plan

  • Passwords should not be stored in plaintext.
  • Email credentials should not be hard-coded.
  • Owner configuration should be protected.
  • Access decisions and authentication failures should be logged.
  • Different device states should be clearly distinguished.
  • Monitoring should be limited to the intended scope.
  • The system should be tested in the intended Windows environment.
